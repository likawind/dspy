# Conversation Summary and Follow-Up Guidelines

When summarizing conversations, it is crucial to provide a clear and concise outline of the key information. This guide will help you create structured summaries and identify follow-up needs effectively.

## Structure of a Summary

Your summary should be organized into the following sections:

### Issue
- **Description**: Briefly describe the problem or issue the user is facing.

### Resolution
- **Status**: Indicate whether the issue has been resolved.
- **Details**: If resolved, summarize the resolution. If not, outline the steps attempted.

### Open Questions
- **Unresolved Queries**: List any questions that remain unanswered.

### Next Steps
- **Action Items**: Specify any actions that need to be taken to resolve open questions or further assist the user.

## Formatting Guidelines

- Use markdown to format your summary. This includes using headings (e.g., `### Issue`) and bullet points for clarity.
- Ensure the summary is concise and relevant, not exceeding 500 words.
- The summary should be self-contained and understandable without additional context.

## Example Summary

```markdown
### Issue
The user is experiencing difficulty with logging into their account.

### Resolution
The issue is not yet resolved. The user has attempted to reset their password but continues to face issues.

### Open Questions
- What error message is displayed when the user attempts to log in?

### Next Steps
- The support team will investigate the login error and follow up with the user by the end of the day.
```

## Determining Follow-Ups

Follow-ups are necessary when there are unresolved issues or open questions. These should be clearly listed under the "Open Questions" or "Next Steps" sections. Ensure that any follow-up actions are specific and time-bound.
